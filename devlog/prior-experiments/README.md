# 前置實驗(2026-09-03)—— 在**另一個**專案上跑的

> ⚠️ 這裡的檔案不屬於活動報名系統。它們來自一個**先前的練習專案**
> (部門揪團訂飲料),那個題目在 2026-09-04 被換掉了。
> 原文照放,一個字沒改 —— 這個 repo 的規矩是「**原文,不要轉述**」。

## 為什麼留著

因為它們是這個系列**唯一一次「我賭錯了」的紀錄**,而且賭得很徹底。

我當時的假設是:AI 寫後端會踩四種典型的錯。所以我埋了四個陷阱,
每一個都對應一種「眼睛看不出來、但機器裁決得了」的缺陷:

| 實驗 | 埋的陷阱 | 結果 |
|---|---|---|
| A1 `exp-a1-schema.md` | schema 會用浮點存金額、狀態機列舉值會漏 | **沒踩** |
| A2 `exp-a2-settle.md` | 分帳會有除不盡的餘數黑洞 | **沒踩** |
| A3 `exp-a3-deadline.md` | 截止判定會把 `Date.now()` 寫進 domain | **沒踩**(它把 `now` 當參數了,問題出在 handler) |
| A4 `exp-a4-race.md` | 併發會先查再寫 | **沒踩** |

**四個都沒踩。**

## 這個結果改變了整個專案

如果 AI 不會踩那四個陷阱,那「等它出錯然後抓包」這條路就是死的。
於是題目從揪團訂飲料換成活動報名 —— 不是因為 AI 更容易在報名系統上出錯,
而是因為報名系統有**更多**「能被機器裁決、而眼睛看不出來」的規則
(規則從 4 條變 7 條,併發從 1 條變 3 條)。

後 10 天真正要打的因此變成另外三件事:

1. 它做對了,但兩個元件對不上 —— 各自都正確,接縫沒人定義
2. 測試全綠而東西是錯的 —— 有一種缺陷不會有任何紅燈
3. **我的尺自己壞了** —— 而我是拿那把尺去量它的

完整脈絡見 `docs/spec.md`、`docs/non-goals.md`,以及 `devlog/LEDGER.md`。
